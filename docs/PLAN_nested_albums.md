# Deep Media — План: вложенные альбомы

Дата: 2026-10-07. Статус: **черновик, ждёт решений ниже**. Код не начат.

В апстриме Immich вложенных альбомов нет, это давний открытый запрос
([discussion #2073](https://github.com/immich-app/immich/discussions/2073)). Делаем у себя,
изменения только добавляющие (новая колонка, новые эндпоинты, новые компоненты), чтобы
обновления Immich вливались без конфликтов.

## Что нужно решить до начала

Рекомендация отмечена **жирным**. Если со всеми рекомендациями согласны, план ниже уже
под них написан.

| # | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| 1 | Что показывает родительский альбом | (а) свои фото + плитки вложенных альбомов; (б) ещё и все фото вложенных | **(а) в v1**. Переключатель «со вложенными» — этап 5: там нужно отсекать закрытые и чужие вложенные альбомы |
| 2 | Влияет ли вложенность на доступ | (а) нет, это только раскладка; (б) участники родителя видят вложенные | **(а)**. Слой доступа (`utils/access.ts`) не трогаем. «Поделиться вместе с вложенными» — отдельной кнопкой позже (этап 5), она просто добавит людей в каждый вложенный |
| 3 | Закрытые альбомы и вложенность | (а) вложенный в закрытый тоже всегда закрыт; (б) замок только на одном альбоме | **(а)**, и правило держится при записи: закрыли родителя — закрылись все потомки; положили альбом в закрытый — он закрылся; открыть вложенный внутри закрытого нельзя. Проверка доступа (`album.isLocked`) остаётся как есть, без рекурсии |
| 4 | Чьё это дерево | (а) одно дерево, раскладывает владелец; (б) у каждого участника своя раскладка | **(а)**: родитель и вложенный должны принадлежать одному владельцу. Участнику общего альбома, у которого нет доступа к родителю, вложенный показывается на верхнем уровне |
| 5 | Что делать с «папками» (`folder`, `PLAN_folders_acl.md`) | оставить / скрыть / слить с альбомами | **Оставить как есть, не сливать в v1.** На проде одна пустая папка «Алтай 06.26». После выхода вложенных альбомов решить, прятать ли создание виртуальных папок, чтобы не было двух похожих иерархий |

Мелкие решения, которые план принимает сам (скажите, если не так):
- **Удаление родителя** вложенные не удаляет: они поднимаются на уровень удалённого. Фото не теряются никогда.
- Глубина — до 8 уровней. Цикл (положить альбом в собственного потомка) сервер отклоняет.
- Обложка, количество и даты родителя — только по его собственным фото. Если своих фото нет, обложка берётся у первого вложенного.
- Публичная ссылка на родителя показывает только его фото.
- Мобильное приложение в v1 видит те же альбомы плоским списком и ничего не ломается (подробности ниже).

## Как устроено сейчас

- Альбом: `server/src/schema/tables/album.table.ts`. Колонки владельца нет, владелец — строка `album_user` с ролью `owner`.
- Список альбомов: `GET /albums`, `GetAlbumsDto` (`shared`, `assetId`) в `server/src/dtos/album.dto.ts`. Мобильное приложение берёт этот же список, поэтому без новых параметров он должен отвечать как раньше.
- Доступ: `server/src/utils/access.ts` (`checkAccess`, ветки `Permission.Album*`), там же отсев закрытых (`withoutLockedAlbums`). Списки фильтруются `notInLockedAlbum` из `utils/database.ts`: asset, download, map, memory, person, search, trash, view-репозитории. При рекомендации 3 ничего из этого не меняется.
- Веб: список — `web/src/routes/(user)/albums/`, `components/album-page/` (`AlbumsList`, группировка `AlbumGroupBy`); страница альбома — `routes/(user)/albums/[albumId=id]/…`. Для дерева есть готовые образцы: `components/folders/FolderGrid.svelte`, `FolderBreadcrumbs.svelte`.
- Мобильное: сгенерированный Dart (`mobile/openapi`, например `AlbumResponseDto.fromJson`) неизвестные поля пропускает. Значит, новое поле `parentId` старым приложениям не мешает. Синк альбомов — `SyncAlbumV2` (`server/src/dtos/sync.dto.ts`, `sync.service.ts`).

## Модель данных

Колонка в `album`:

| Колонка | Тип | Назначение |
|---|---|---|
| `parentId` | uuid, null, FK → `album.id`, `ON DELETE SET NULL`, индекс | родитель; `null` — верхний уровень |

Почему не closure table, как у папок: альбомов единицы-сотни, дерево неглубокое, рекурсивного CTE хватает. Закрытая таблица — это лишняя синхронизация при каждом перемещении.

Миграция `1791400000000-AddAlbumParent`: только добавляет колонку. Отчёт о расхождении схемы должен остаться «No schema drift detected».

## Этапы

### Этап 1. Сервер
- `AlbumTable.parentId`, миграция.
- DTO:
  - `AlbumResponseDto`: `parentId`, `albumCount` (вложенных, видимых пользователю);
  - `CreateAlbumDto`: `parentId`;
  - `UpdateAlbumDto`: `parentId` (перенос; `null` — на верхний уровень);
  - `GetAlbumsDto`: `parentId` (uuid или `root`). Без параметра ответ как раньше: все альбомы плоско.
- `GET /albums/:id/ancestors` — хлебные крошки. Только предки, которые пользователь может читать.
- Проверки переноса в `AlbumService`:
  - `AlbumUpdate` на оба альбома;
  - один владелец;
  - родитель не потомок переносимого;
  - глубина ≤ 8;
  - правило закрытых (решение 3).
- Удаление: потомки поднимаются к деду, в той же транзакции.
- Закрытие и открытие родителя каскадом по потомкам (одним рекурсивным `UPDATE`).
- События для веба и аудит-лог на перенос.

### Этап 2. API-клиенты
- Перегенерировать OpenAPI и TypeScript SDK.
- Dart — отдельной задачей вместе с мобильным этапом.

### Этап 3. Веб
- `/albums` — только верхний уровень. На плитке — счётчик вложенных. Поиск по названию ищет на всех уровнях и показывает путь.
- Страница альбома:
  - крошки по образцу `FolderBreadcrumbs`;
  - над фото — ряд вложенных альбомов по образцу `FolderGrid` / `AlbumCard`;
  - кнопка «Новый вложенный альбом».
- Действие «Переместить в…» — модалка с деревом, нельзя выбрать себя и потомков.
- «Добавить в альбом» — список с отступами по уровням или с путём.
- Закрытые: замок у потомков закрытого, переключатель «Закрытый» у потомка неактивен с подсказкой.
- Переводы ru/en.
- Перетаскивание альбома в альбом — позже.

### Этап 4. Мобильное приложение (бэклог, вместе с закрытыми альбомами из ROADMAP §6)
- v1 ничего не делает: старые и текущие сборки показывают все альбомы плоским списком.
- Потом:
  - `parentId` в синк (`SyncAlbumV2` или новая версия);
  - колонка в локальной базе (drift);
  - экран с вложенными;
  - Dart-клиент.

### Этап 5. Потом
- Переключатель «показывать фото вложенных» в родителе, с отсевом закрытых и недоступных.
- «Поделиться вместе с вложенными».
- «Превратить папку в альбом» (ROADMAP п. 5): папка с подпапками → дерево альбомов. Это главный потребитель вложенности.
- Решение по виртуальным папкам (решение 5).

## Как проверять

Только на копии базы, **никогда с подключённым NAS** (рецепт локального запуска — в заметках по закрытым альбомам: копия базы, пустой `IMMICH_MEDIA_LOCATION`, `IMMICH_IGNORE_MOUNT_CHECK_ERRORS=true`).

Сервер, unit и medium-тесты:
- перенос: в себя, в потомка, глубже 8, в чужой альбом, без прав — отказ;
- удаление родителя поднимает потомков, фото на месте;
- закрытие каскадом:
  - перенос в закрытый закрывает;
  - нельзя открыть потомка закрытого;
  - фото потомка не видны в ленте, карте, поиске и памятях без PIN;
- `GET /albums` без параметров отвечает как раньше: плоско и с тем же составом;
- участник общего вложенного без доступа к родителю видит его на верхнем уровне, крошки не раскрывают имя родителя.

Веб, Playwright на копии:
- создать дерево из трёх уровней;
- перенести;
- удалить середину;
- закрыть корень и пройти по дереву с PIN;
- при истёкшем PIN — экран PIN, а не ошибка (как в фиксе `7ccc50a`);
- телефон 390 px и десктоп, тёмная и светлая темы.

Мобильное: собранное приложение открывает альбомы как раньше, без падений на новом поле.

## Выкладка и риски

- **Есть миграция**, в отличие от веб-фикса. Порядок выкладки:
  1. `pg_dump` в `/opt/deep-media/backups`.
  2. Патч-слой с `server/dist` и `web/build` поверх `:7ccc50a`. Слой годится, только если `package.json` и `pnpm-lock.yaml` не менялись — проверить.
  3. Веб собирать с `IMMICH_BUILD`.
- Откат — только вместе с восстановлением дампа: старый образ не стартует на базе с новой миграцией.
- **Утечка закрытых при каскаде.** Главный риск. Закрывается правилом при записи (решение 3) и тестами на все списки с `notInLockedAlbum`.
- **Мобильное уже сейчас** показывает фото закрытых альбомов (ROADMAP §6). Вложенность это не ухудшает, но и не чинит.
- **Апстрим.** Конфликты возможны в `album.table.ts`, `album.dto.ts`, `album.service.ts` и на странице альбома. Свои куски держать отдельными функциями и компонентами.
- **Две иерархии** (папки и вложенные альбомы) могут путать — см. решение 5.
